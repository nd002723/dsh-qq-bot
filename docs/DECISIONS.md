# 决策记录

> 只记「为什么这么定」，不记讨论过程。每条标 **已定**（已落地）或 **未定**（等维护者口径）。

## 2026-11-15：内部审查整改中的四个取舍

背景：三轮只读审查（240 + 63 条发现）之后的一批修复。下面四条**不是「怎么改」的问题**，
而是「要什么」的问题 —— 前两条已按下面的结论落地，后两条仍是未定。

### 1. CQ 字符串入站 —— 已定（诚实降级 + 运行时告警）

**现状**：段数组路径（`post_format=array`）没有这个问题；只有拿到 CQ 字符串时才有。
**注意 `post_format` 是协议端（NapCat 等）的配置，不是本插件的**：代码里既不读取也不设置它，
所以不存在「插件默认是 array」这回事 —— 这条边界能不能闭合，取决于运维有没有在协议端配 array。

**为什么没有「修」**：三种写法都不成立（详见 `docs/SECURITY.md` 的「CQ 字符串入站」一节）——
最关键的实证：把 `&#91;` **还原成真方括号**会让「已转义、本该安全」的手打串从 0 个匹配变成 1 个（实测 0→1），
**等于亲手把伪造的 @ 变成真 @**。而把 `&#91;` 换成全角占位符才是空操作（已转义的串里本来没有裸 `[`，
换不换都不匹配）。两种做法要分清 —— 前者有害，后者无用。

**决定**：接受「信任协议端」这个前提，把边界写进 `docs/SECURITY.md`，并在首次收到 CQ 字符串时打一次 warn。

抽取逻辑本身**零改动**（没有任何「挡住伪造」的企图，因为做不到）；新增的只是那条 warn。
所以落地是 `docs` + 一个 `feat`（运行时提示），**不是**把问题修掉了。

**未采纳的两条根治路径**（都改变兼容面，需要单独决定）：
- 要求协议端必须 `post_format=array`（对只给 CQ 串的实现端是破坏性变更）；
- 不再支持 CQ 字符串入站（砍功能）。

### 2. `proactive.idleTimeoutMs = 0` —— 已定（允许，作为显式「关掉保护」）

**语义**：设 0 = 不设上限，于是超时路径（含取消残留回合与 fail-closed）永远不会触发。

**决定**：保留这个值，并在设置页 hint 里写清代价（「0 = 不设上限，等于放弃这层保护」）。
理由：「能用的开关 + 写清代价」比「藏起来」更诚实 —— 设成 0 是一个**明确表达的意图**，不是手滑。

（先前这里写过「设置页的数字框会夹到 min/max」，那是**错的**：客户端只对 `slider: true` 的字段做夹取
（`lib/client/settings.js:1002` 的 `hasSlider` 分支），而 `idleTimeoutMs` 是核心组 22 个 number 字段里
唯一没有 `slider` 的那个 —— 所以填 99999999 不会被夹回去。结论不变，但理由要换成上面那句。）

**备选（未采纳）**：把 min 抬到 1000、拒绝保存 0。理由是「安全保护不该可被配置关闭」——
那是产品口径，不是技术判断；当前不采用。

### 3. 切换协议时旧名单保留还是清空 —— 已定（保留，暂不加启动告警）

**现状**：`auth.superAdmins` / `group.allow` / `private.allow` / `admin.manageGroups` / `proactive.groups`
这几份名单在切换协议（OneBot ↔ QQ 官方）后语义就变了（QQ 号 vs OpenID），插件不动它们、也不提示。

**决定**：保留旧值，**不加**启动告警。
- 清空 = fail-open（名单空了在很多配置下等价于「所有群都放行」），比留着旧值更危险。
- 告警要「按当前协议判断某个 id 形态是否可能合法」，而 OpenID 形态并不唯一 —— **启发式必然误报**，
  一条每次都出现的假告警会把真告警淹掉。

**若要加**：只报「当前协议是官方、而名单里全是纯数字」这一种**确定不合法**的组合（窄口径，未实现）。

### 4. 主动回合超时后的身份恢复 —— 已定（两份都 fail-closed）

**曾出现的问题**：只让 `dshAllowed` 在超时后保持 false，`turnSpeaker` 仍被无条件恢复。
而 `qqgroup` 的鉴权**不走** `dshAllowed`：它读 `currentSpeaker(entry)` → `resolveAuthority(...)`，
`currentSpeaker` 又优先读 `entry.turnSpeaker`，且 `qqgroup` 在访客白名单里直接放行。
于是超时窗口里（`finally` 已跑完、`whenIdle` 还没 resolve），被 cancel 的残留回合仍可能拿着恢复后的
发言人快照（可能是拥有者）去驱动群管理动作。

**决定**：两处恢复合成一个判据 —— `timedOut !== true` 时都恢复，超时则都不恢复。
**不会污染下一次正常回合**：`turnSpeaker` 每次 `runTurn` 开头都会重写，且所有写点都在 `entry.queue` 串行链里。

**备选（未采纳）**：超时也恢复 `turnSpeaker`，但给 `qqgroup` 单独加一条「本回合已超时则拒绝」的判据 ——
效果一样，措辞更可控；若将来觉得「超时后 qqgroup 回未授权」观感别扭，可切到这条。
