# 安全策略

本插件把 QQ 消息转给 DSH Agent，涉及工具权限与凭据。支持的版本：最新 `main` 与最近一个 tag。

## 报告渠道

- **不要**在公开 issue 里贴 access_token、QQ 号、服务器地址、Agent 工具输出。
- 发现权限绕过、命令注入、凭据泄漏一类问题，走私信：开一个只写「安全问题，请私聊」的 issue（不写细节），或直接联系维护者 [@arrow1031](https://github.com/arrow1031)，再要不加联系方式里的群私聊群主一下也行（不一定能及时回，但是问题正常合理的情况下肯定会想办法处理）。
- 目标响应时间：48 小时内首次回复；确认后 7 天内给出修复计划。

## 拥有者设置通道（qqconfig）的威胁模型

0.10 起拥有者可以在 QQ 私聊里让机器人改一部分设置。这条通道按「能被社工、也能被自己手滑」设计：

- **身份不可伪造**：判定依据是当前 QQ 会话最近一条消息的发言人，不是工具参数里的字符串；插件重启后待确认的 token 全部失效（只存在内存里）。
- **场域限制**：只在拥有者私聊里可用；群里调用直接拒绝。
- **字段白名单**：`auth.*` / `onebot.*` / `imageGen.*` / `webSearch.*` / `proactive.model` / `proactive.speakProvider` / `proactive.speakModel` / `mode` / `adapterPath` 等硬拒绝，即使有人误加进白名单也会被 `DENY_PREFIXES` 二次挡下——机器人无法通过这条通道给自己扩权。
- **两步确认 + 修订号**：`propose` 不落盘；`apply` 时若配置已被设置页改过（revision 变化）则作废。
- **落盘不经手 YAML**：只调 DSH settings 服务（schema 校验、原子写、热重载）；服务不可用时拒绝，不退化成手写 `cordis.patch.yml`。
- **限流与审计**：默认每小时 6 次 / 每天 30 次；每次结果追加到 `QQ_msg/qqbot-config-audit.jsonl`。
- 总开关 `auth.ownerSettings`，关掉即彻底禁用。

发现任何绕过（非拥有者触发写入、白名单外的字段被改、审计缺失）请按上面的渠道私信。

## 流程授权（0.12 起，默认关）

给「子代理 / 队友 / 工作流」这四个高危编排工具加一道私聊动态码，默认 `flowAuth.enabled=false`（关着时行为与 0.11 相同）：

- **默认关就等于没装**：关着时既不接管工具面、也不拦截 `/auth` `/flow` 消息。
- **动态码只在私聊**：只认拥有者 + 私聊 + 消息首位；命中即拦截，不进 Agent 回合，动态码不落会话历史（还会先剥掉零宽等不可见字符，防 `/auth` 被前置字符绕过）。
- **一次一用 + 30 秒**：一条授权只放行一次调用，`grantTtlSeconds` 默认 30 秒；同一个 30 秒窗口的动态码不能重放；连续错 5 次锁 15 分钟；待授权申请本身也会过期。
- **身份快照**：闸门读的是本回合开始时固化的发言人，排队期间别人插话不会改判已有回合（工具层同样读快照）。
- **产物有边界**：只打包本会话目录里本轮的新文件，符号链接与隐藏文件跳过，文件名统一加 `./` 前缀并拒绝含换行的名字。
- **恢复码**：scrypt 哈希存配置、明文只在终端打印一次；用掉后插件会把对应哈希删掉，写盘失败才需要手动清理。

## CQ 字符串入站：一条依赖协议端的边界（0.14.x）

插件优先走**段数组**（`post_format=array`，也是默认与现网配置）。只有拿到 **CQ 字符串**时才走下面这条路径，
而它有一个**插件无法单方面保证**的前提：

- 协议约定把正文里的方括号转义成 `&#91;` / `&#93;`。遵守约定时，用户手打的 `[CQ:at,qq=…]` 不含裸 `[`，
  天然匹配不上抽取正则，不会被当成真正的 @。
- 但 `post_format` 是 **OneBot 11 实现端的可选项**。实现端不转义时，手打文本与协议层给出的段**字节完全相同**，
  任何正则都区分不了 —— 想「挡住手打」就等于把正常 @ 一起吃掉。

所以这条边界的正确定性是「**信任协议端**」，而不是「已保证安全」。具体后果（未转义时）：
`mentions` 可被伪造从而绕过 `group.requireAt`；`replyTo` / `imageUrls` 同理（同一条正则族）。

**缓解**：首次收到 CQ 字符串形态的消息时，适配器会打一条 warn（这本身就是「协议端没配 array」的确证），
提示把 `post_format` 设为 `array`。只提示一次，不刷屏。

**为什么不在插件里根治**：写过三种修法都不成立 —— 靠协议端转义（就是上面说的前提）；抽取前还原 `&#91;/&#93;`
（实测**空操作**：已转义的串里本来没有裸 `[`，替换前后正则匹配数都是 0）；连未转义的裸 CQ 码一起挡
（做不到也不该做）。真要根治只有两条路：要求协议端必须 `post_format=array`，或不再支持 CQ 字符串入站 ——
两者都改变兼容面，属于产品决策，未采纳。

## 主动回合的超时与身份

主动发言会触发一个真实回合。`proactive.idleTimeoutMs`（默认 180000，`0` = 不设上限）限制它最长占用时间。

- **超时会取消残留回合**：不取消的话那个回合会一直占住 `whenIdle()`，导致下一条用户消息被静默丢弃、
  还回一句「本轮没有产生文字回复」。
- **超时后两份身份都不恢复（fail-closed）**：`dshAllowed=false` 之外，`turnSpeaker` 也保持访客快照。
  原因是 `qqgroup` 的鉴权**不走** `dshAllowed`，它读 `currentSpeaker(entry)` → `resolveAuthority(...)`，
  而 `qqgroup` 在访客白名单里直接放行 —— 只把 `dshAllowed` 置 false 时，残留回合仍能拿恢复后的发言人快照
  驱动群管理动作。
- **设 `0` 等于关掉这层保护**：超时路径（含取消与 fail-closed）永远不会触发。
